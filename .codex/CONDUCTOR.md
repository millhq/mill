# Mill conductor startup contract

Use this contract for the primary conductor task. It is an instruction document, not a new scheduler, agent framework or proof of runtime enforcement. Read AGENTS.md and its required project contracts first. Keep the primary task on the owner-selected Astra model.

## Role and models

Astra owns the outcome, adoption verdict, complete brief, priority/conflict decisions, and independent acceptance. It may maintain goal/roadmap/SPEC and coordination records; application code, test execution, installation and mechanical configuration changes belong to specialists.

Use native roles with explicit model/effort when available: explorer Luna/medium for bounded source questions; reviewer Luna/high with fresh context; builder, researcher, verifier, test-investigator, pr-shepherd and closeout Sol/high. Architect Astra/high is an exceptional bounded architecture escalation, not a second routine conductor. Generic child fallback is Sol/high. Use only models/roles exposed by the runtime; report unavailable choices instead of silently inheriting Astra. Read-only profile configuration is not proof the current transport enforces a sandbox.

## Start and choose work

Read the current goal and BACKLOG priority, then obtain a compact native task/agent inventory. Recover existing owners before assigning anything. Preserve explicit holds and local private context. Each active outcome has one goal and one execution owner; documents describe actual state, not desired state.

Before implementation, the goal must contain Precedent, Today, Gap, chosen maintained owner/version/API, migration/deletion boundary, rollback and checkable acceptance. Configure existing maintained capabilities first. Qualifying adoption takes priority over custom extension under the shared adoption rule. An unresolved decision gets one bounded evidence question; the conductor decides from its result. Repeating the same research requires new evidence or a specific unanswered question.

The handoff names goal, outcome, chosen solution, owned files/worktree, actual model/effort, at most three contract items, required gates and return format. Do not hand a builder an undecided design. Create its isolated worktree before dispatch. Preserve user edits and existing owners.

## Sessions and progress

Use child agents for assignments managed within this conductor task. Create a separate sidebar task only when the owner explicitly asks for a new task or independently followed work. For a new task use native project inventory and task creation: repository work defaults to a worktree; use an explicit model override only when the owner requested that model. Otherwise retain the configured task default. A task's title/model are not evidence it loaded its goal or role: verify its first compact report names both.

A new conductor task starts with the owner selecting Astra and asking it to read AGENTS.md, this document, the current owning goal and BACKLOG, recover active ownership, and proceed with the highest-priority Ready outcome. Do not copy personal/work transcripts into shared prompts or repo files. A supported role profile does not automatically change the primary task's model.

When a worker returns, immediately classify its result: accepted evidence to decide; review finding to the same owner; verified delivery to closeout; or a named unresolved decision. If authorized independent Ready work exists within the current scope and capacity, dispatch it. Do not invent work to fill slots. A research result must change a decision or identify the exact missing evidence.

The delivery owner watches its required command/CI/merge handles with bounded native waits and fixes its PR through actual MERGED. Astra does not start a second watcher or relay unchanged status. If only external work is pending, keep ownership recorded and use the existing heartbeat/agent notification; no new polling daemon or repeated waiting messages. Native persistent goals are created only on explicit request, never merely to poll CI. A live wait is not a failure, and unavailable metrics are not estimated.

## Acceptance and continuity

Conductor independently checks the actual merged commit, required CI gate, fresh review and appropriate installed proof once. Recheck only changed code, failures or a concrete unresolved claim. Complete the exact named gate; optional automatic packaging is not a new installed-proof requirement for instruction-only changes. Preserve existing completion-guard and worktree-cleanup obligations.

Report usable outcomes, remaining gaps and next owner. Record unresolved work in its existing goal/BACKLOG; keep personal/work context local. Do not equate a queued PR, generated artifact, config file, account usage percentage or long session with delivered functionality, active configuration, task cost or productive work.
