For the original branch patches, the base is their merge base with `origin/main` at capture time and the head is the local branch tip. The `activation-contract` and `vault-recovery` patches capture only the unmatched local tip commit relative to its parent, after the corresponding PR merged; they are not full branch snapshots. For a working-tree patch, base and head are the checkout commit; the patch captures its unstaged changes and selected untracked files. The `codex/revert-shared-usage-guardrails` tip has the same tree as its base, so there is no code patch to apply.

To inspect or restore one patch, create a clean temporary worktree at its listed base commit, then run `git apply --check <patch>` and `git apply <patch>`. Apply each patch separately; the snapshots may overlap and are not rebased onto current main. The recorded SHA-256 detects accidental artifact changes.

The private recovery bundle is held separately and is not part of this repository. Excluded prose remains available in the private bundle; these patches are code-only recovery material.

A further nine local tips differed from their recorded PR heads. Three were agent-context-only and already present on main (`chore/rules-highest-abstraction`, `chore/rules-no-reimplement`, `codex/shared-usage-guardrails`); two only merged other commits (`goal-0305-s4a-step-test`, `goal/0383-reviewer-agent`); two code commits were patch-equivalent to main (`goal/0354-diagram-chrome`, `goal/0354-followups`). The two remaining code commits are preserved as `activation-contract.patch` and `vault-recovery.patch`. This classification compares commit deltas and patch equivalence, not feature behavior or runnable state.

Validation: every nonempty patch replayed with `git apply --cached --check` against a fresh index at its listed base; replayed binary diffs matched the recorded patch bytes. Patch paths were checked against the public exclusions, and Gitleaks found no leaks in the archive.
